- [x] Fixed: `$resultRows += $row` in both `Invoke-GovernedDeletionFromExcel.ps1` and `Find-GovernedCandidatesByScan.ps1` was O(n^2) (PowerShell rebuilds the whole array on every `+=`) - impractical past roughly tens of thousands of rows. Now uses `List[object]` (O(1) amortized `.Add()`). `Write-Progress` calls were also unthrottled per-row; now throttled to the same cadence as the console status line.
- [x] Fixed: worksheet auto-selection (`-WorksheetName` omitted) used to blindly pick the first sheet by position, which broke with ImportExcel's own "does not contain any data in the row/s after the top row of '1'" error whenever that first sheet was an empty cover/instructions tab. Now probes each sheet (cheaply, via `Select-Object -First 1` short-circuiting the pipeline) and picks the first one that actually has data.
- [x] Fixed: the write-back used to rebuild the ENTIRE sheet via `Import-Excel` + `Export-Excel -ClearSheet`, which silently reset every column's original Excel formatting (number/date formats, currency, column widths) to ImportExcel's defaults - not just the four new columns'. `Update-ExcelWithResults` now opens the workbook directly (`Open-ExcelPackage`) and edits only the `CleanupStatus`/`CleanupDetail`/`CleanupTimestamp`/`CleanupBy` cells for rows actually processed this run, leaving every other cell (and its formatting) untouched. This also means the write-back cost now scales with rows *processed*, not total rows in the sheet.
- [x] Fixed: reading the candidate Excel used to be a single opaque `Import-Excel` call with zero progress feedback - on a workbook with hundreds of thousands of rows, the console could sit silent for minutes with no way to tell it wasn't hung. `Read-GovernedCandidateRows` now reads row by row via direct cell access (only the path + existing `CleanupStatus` per row, not every column) and reports live "Read N / Total rows" progress the same way every other phase in this package does. As a side effect this also uses less memory than materializing a full typed object per row for every column.
- [ ] The `Open-ExcelPackage`/`Close-ExcelPackage` cell-editing and row-reading approach hasn't been validated against a real multi-column, custom-formatted ManageEngine export yet - do that as part of the dry-run testing in the top item on this list, specifically checking that (a) unrelated columns (dates, sizes, custom number formats) look identical before/after a run, and (b) a genuinely large (100k+ row) export reads and completes in a reasonable time.
